一、一位志工從申請到打卡，系統怎麼認得他

先記住一件事：志工在本平臺沒有自己的密碼。他用借書的那組帳號密碼登入。那組帳密存在館藏查詢系統，也就是圖書館管讀者帳號與借書的系統：產品名叫 HyLib，讀者登入的網站叫 webpac。本平臺只做兩件事：把帳號密碼轉給館藏查詢系統問「對不對」；自己保管一份「誰是志工」的名冊。名冊靠「讀者識別」對到人。讀者識別是讀者在館藏查詢系統裡的內部編號，換證、改名都不會變。

第 1 步　還不是志工的讀者，在前台填「志工申請」 不用登入。填八欄：姓名、借閱證號、身分證字號、聯絡電話、電子郵件、申請服務地點、申請組別（可多選）、可服務時段。送出時，系統拿借閱證號問館藏查詢系統「這張證存在嗎、是個人證嗎」。查無此證就不受理。送出後出現申請編號，狀態「資料審核中」。系統通知那個地點的管理者。
為什麼要填身分證字號：為了防止別人冒查申請進度。借閱證號印在證上、櫃檯也看得到，不算秘密。如果只憑證號就能查，任何人輸入別人的證號，就看得到他有沒有申請、叫什麼名字。所以查進度時，要「借閱證號＋身分證字號末四碼」兩個一起對。身分證字號只留在申請表，審核通過後不會複製進志工名冊。
第 2 步　地點管理者在後台「新進志工審查」審核 三個階段：資料審核中 → 待面試 → 通過（或未通過）。每推進一步，系統寄一封 Email 給申請人。按「通過」的那一刻，系統才在志工名冊建一筆資料：記下他的讀者識別、產生志工編號、狀態設為「在職」。從這一刻起，他登入就進得來。
第 2 步的另一條路　上線時已經在服務的幾百位志工：用 Excel 一次匯入名冊 這些人不用重新申請。承辦人在後台「志工管理 › 匯入志工名單」上傳 Excel，欄位是：志工編號（選填）、姓名、借閱證號、組別、服務地點、聯絡電話、電子郵件、加入年度。
為什麼 Excel 沒有身分證字號：匯入只要知道「這張借閱證是哪一位讀者」。系統拿每一列的借閱證號去問館藏查詢系統，換回讀者識別，寫進名冊。查不到的那一列不匯入，畫面會列出原因。這個過程用不到身分證字號，也不該讓承辦人在 Excel 裡傳一整欄身分證字號。
第 3 步　志工登入前台 首頁登入區：帳號填借閱證號或身分證字號，密碼填館藏查詢系統的密碼（跟他在 webpac 個人書房用的同一組），填驗證碼，按「會員登入」。系統做兩關：
  1. 第一關，他是不是讀者：把帳號密碼送到館藏查詢系統的「會員登入」API。API 是館藏查詢系統開放給別的系統呼叫的功能，一支 API 只做一件事。密碼對、而且是個人證，API 就回傳這位讀者的讀者識別與目前的借閱證號。密碼錯就顯示「帳號或密碼錯誤」；連錯 3 次鎖 30 分鐘。
  2. 第二關，他是不是志工：本平臺拿讀者識別去志工名冊找。找得到、狀態是在職或停權，就進去（電腦進儀表板、手機直接進現場簽到退）。找不到，顯示「查無志工資格，請洽所屬服務地點承辦人」。
忘記密碼、改密碼、辦借閱證，都是點連結到館藏查詢系統去辦，本平臺沒有這些畫面。

三、筱儒的問題是在問什麼、怎麼回

她週末把規格書與原型丟給 AI，請它找出開發時會卡住的地方：文件沒寫的，或規格書與原型寫得不一樣的。AI 列出的每一條叫一個 TBD（還沒定的事）。每一條都是一個情境：「遇到某某情形，系統要怎麼做？」

回法只有三種，每題對號入座（第四節「哪一種」那欄用同一組名字）：

  1. 規格書有寫：直接講答案、說在哪一節。（例：登入方式、個資欄位）
  2. 原型與規格書不一樣：照 11/6 定的原則「以原型為準」，今天當場定，我回去改規格書。（例：請假單誰審、記點從哪天起算）
  3. 兩邊沒寫：今天當場定，三個原則：不新增後台參數、不拿去問客戶、讓志工少做一步。（例：撤回請假單、活動改期要不要通知）

第四節的表每題都標好是哪一種、怎麼講。會上不要說「這是好問題，我再跟客戶確認」，昨天如慧特別點名不要這樣。
