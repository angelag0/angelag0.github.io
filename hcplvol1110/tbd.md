# 志工服務管理平臺　TBD 回覆（2026-11-10 問題討論會議結論）

依據：11/10 11:00 會議（Simmy、如慧、Jason、筱儒）。下表結論今天起照著開發；跟現行原型或規格書 1.3 不一致的地方，以下表為準。原型改版與規格書 1.4 於 11/11 提供：「規格書改哪裡」欄是 1.4 會改的節，「原型」欄是原型會改的畫面。下表沒提到的照原則：畫面、欄位、按鈕、流程以原型為準，原型看不到的規則照規格書。

| 題號 | 結論 | 規格書改哪裡 | 原型 |
|---|---|---|---|
| TBD-002 個資落地 | 系統不存身分證字號：志工申請表拿掉這一欄（剩姓名、借閱證號、聯絡電話、電子郵件、申請服務地點、申請組別、可服務時段），申請進度查詢改用「借閱證號＋電子郵件」；登入帳號欄仍可輸入身分證字號，只送館藏查詢系統驗證、不落地。資料庫加密：聯絡電話、電子郵件。不加密：姓名、借閱證號（要當查詢與刷證比對條件）。沒有地址、出生日期、性別欄位。畫面遮罩：後台志工名冊清單預設遮住姓名、聯絡電話、電子郵件、借閱證號；按眼睛圖示顯示全文，並寫一筆操作紀錄。明細視窗與志工本人的個人資料頁不遮。尚未定：各欄露出幾碼，向館藏查詢系統端確認後寫進規格書 1.4。 | F-12、F-15、B-02、B-03、新增 2.9 個資欄位與加密遮罩 | 前台志工申請表與進度查詢、後台新進志工審查與志工名冊 |
| TBD-003 登入實作 | ①志工登入：帳號填借閱證號或身分證字號，密碼填館藏查詢系統的密碼。本平臺把帳密轉送會員登入 API，先確認是讀者、而且是個人證（第一關）；再拿 API 回傳的借閱證號到本平臺志工名冊找人，確認是志工（第二關）。②本平臺不存志工密碼；「忘記密碼」與「辦證」連到館藏查詢系統。③後台管理者帳號由本平臺自建：新增帳號後，系統寄「設定密碼」信到該帳號的電子郵件，本人自設密碼，本平臺加密保存。④志工名冊以借閱證號為唯一鍵；志工編號是館方管理用的選填欄位。志工資格以本平臺名冊為準，不向館藏查詢系統要志工註記。⑤會員登入 API 由 K 部門於 11/16 那週提供；到位前先做假登入，介接處留介面。⑥尚未定：讀者證過期、掛失、停權時怎麼擋，以及讀者補發新證換了證號怎麼對回同一人，等 API 回覆欄位確定後補進規格書 2.7。 | 2.7（加「誰用什麼登入」對照表、讀者證狀態一段）、F-02、B-17 | 不改 |
| TBD-009 新增違規類型的「由出勤異常自動帶入」 | 自動帶入只對應系統內建三種（遲到、早退、缺勤），一對一固定。館方新增的類型一律「管理者開立」，表單上沒有自動帶入選項。內建三種可改點數、不能刪。 | B-14 違規類型分頁、B-07 第 4 點 | 後台「館別與系統參數 › 違規類型」新增表單拿掉該選項 |
| TBD-010 館內網路 IP 是否支援 IPv6 | 欄位長度照 IPv6 設計，IPv4 與 IPv6 都接受；多組以頓號分隔，可填單一 IP 或網段。 | B-14 服務地點欄位說明 | 不改 |
| TBD-013 「我的補登申請」近三個月 | 照日曆月：送出時間在「今天往前 3 個月」以內。往前推到的那個月沒有同一天，就取該月最後一天。這跟長假、記點失效日（TBD-020）用同一支加月份函式，全系統只有這一支。原型目前用 92 天，改成這支函式。 | F-06 第 6-1 點 | 前台改用同一支加月份函式 |
| TBD-014 補登那天沒有該時段的場次 | 補登一律掛既有場次，不自動建場次。那天沒有場次，就不能補登。後台「補登出勤」流程改為：先選志工 → 系統列出這位志工有排班、而且出勤異常（缺勤、有簽到沒簽退、遲到、早退）的場次 → 選一場 → 填簽到、簽退、補登原因。志工端「申請補登」同樣從本人的異常場次挑選，不再自填日期、地點、時段。 | B-06 第 10 點、F-06 第 6 點與欄位說明、2.8.4 | 後台補登出勤視窗、前台申請補登表單 |
| TBD-016 志工撤回尚未核准的請假單 | 可以。「我的申請紀錄」卡片在待代理人回覆、待管理者審核、待文化局簽核三種狀態有「撤回」；撤回後狀態「已撤回」、原排班不變。撤回時通知：代理人已按同意的，通知代理人；請假單已到「待管理者審核」或之後的，通知地點管理者。 | F-07、B-05、4.18 請假狀態、F-11 通知事件 | 前台請假頁加「撤回」 |
| TBD-017 長假代理人承接全部的班，某幾班有衝突 | 送出前逐班檢查代理人接不接得了，條件同後台「手動指定代班人」：在代班範圍內（系統參數，預設限同大組）、在職、同時段沒有班。接得了的班改給代理人；接不了的班自動轉為空缺班，標「長假釋出」。送出前畫面列出會轉空缺的班，但不擋送出。通知三種人：申請人（哪幾班改給代理人、哪幾班轉空缺）、代理人（承接哪幾班）、地點管理者（哪幾班轉空缺、待安排）。 | F-07 第 2-1 點、B-05 第 7 點、F-11 通知事件 | 前台長假表單加檢查與提示 |
| TBD-018 請假單由哪個地點的管理者審 | 申請人所屬任一服務地點的管理者都看得到、都能審第一關；長假第二關（狀態「待文化局簽核」）由總管理者簽核。 | B-05 運作方式 | 不改（原型已是這樣） |
| TBD-019 代班成立（沒有請假單）時原排班者那筆怎麼記 | 班表那一筆直接換成代班人，不另存「已代班」狀態。原排班者的軌跡在代班紀錄（誰的班、誰代、什麼方式、通知過誰、第幾次）。報表的請假統計只算請假單，代班不算請假。 | B-05 第 13 點、B-10 | 不改 |
| TBD-020 記點失效日 | 從「發生日期」起算。加月份遇月底取該月最後一天（1/31 加 1 個月＝2/28）。失效日在開立當下算好存起來，之後改保存期限不回頭重算。 | B-07 運作方式與第 1、3 點、1.0.6 | 記點失效日改用同一支加月份函式 |
| TBD-023 活動報名的時間限制 | 報名與取消都到活動開始時間為止，開始後按鈕變「已開始」不能按；管理者在報名名單手動加入不受限，到活動結束前都可以。活動 QR 從活動當天 00:00 起受理，到活動結束時間失效。不另加參數。 | F-09 第 5、8 點、B-08 第 7 點 | 前台報名按鈕加「已開始」狀態 |
| TBD-024 活動異動 | ①結算後可以改出席再按一次「儲存並結算時數」，以最新勾選覆蓋、時數重算，寫操作紀錄；已匯出的歷史報表不回改。②改日期、時間或地點時寄信給已報名者，套用「班表異動」通知範本，不新增範本（自動通知範本維持十五份）。③提供「取消活動」：填原因、通知已報名者、活動留在清單標「已取消」、不能再報名；不做實體刪除；已結算的不能取消。 | B-08、4.18 活動狀態 | 後台活動管理加「取消活動」 |
| TBD-027 首頁公告輪播的圖 | 每則公告帶一張圖：後台公告欄位加「圖片」（選填；沒上傳時用系統預設圖）。首頁輪播與公告內頁都顯示這張圖。首頁最上方的主視覺橫幅是固定圖檔，與公告無關。 | B-16 公告欄位、F-01、F-13 | 後台公告表單加圖片欄；前台首頁輪播與公告內頁顯示圖 |
